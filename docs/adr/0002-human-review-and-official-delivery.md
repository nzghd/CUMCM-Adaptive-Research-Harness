# ADR-0002：人工审核与官方交付必须分离

- 状态：已采纳
- 日期：2026-09-04
- 适用版本：5.1

## 背景

Gate 已有机器可读的 JSON/CSV 与统一 Markdown 摘要，但若 `approve` 在同一次
调用中自动生成摘要，人可以在未阅读时直接完成批准。另一方面，历史 `package`
包含具名审批、回执和内部状态，适合审计留档，却不满足官方支撑材料的匿名边界。
AI 声明也不能只在日志非空时出现，因为官方规则要求所有队伍声明“未使用”或
“已使用”。

## 决策

1. Gate 使用 `review → 人工打开阅读 → approve`。`review` 是唯一摘要写入入口；
   `approve` 只验证已有摘要、证据链接、正文哈希和底层输入哈希。摘要缺失、
   过期或被修改时失败关闭，不自动生成或修复。
2. 默认论文计划在参考文献前设置 `085_ai_usage_declaration.md`。所有队伍填写
   `AI工具使用声明`；未使用时采用官方逐字句，使用时采用官方格式并与
   `AI_USAGE_LOG.jsonl` 一致。
3. 官方支撑材料由 `build-support` 的显式 allowlist 构建为
   `deliverables/official/支撑材料.zip`；具名回执只放在
   `deliverables/internal/SUPPORT_PACKAGE_RECEIPT.json`。论文 PDF 与支撑 ZIP 分开，均限制为
   `20,000,000` bytes；支撑文件内容、文件名和元数据必须匿名。有需披露 AI
   使用时，ZIP 必须包含当前已核验的 `AI工具使用详情.pdf`。
4. `package` 保留为具名内部审计归档。它不得复用为官方支撑材料，也不得因
   方便而把内部审批、日志或 receipt 混入匿名 ZIP。
5. 构建人姓名和 ZIP 哈希保存在 ZIP 外的内部 receipt 中。机器扫描负责已知
   身份字段、可检索文本、文件名、元数据和大小；图片及完整渲染页面仍由队员
   人工核验。

## 后果

- Gate 审批多一个必须由人完成的阅读停顿，但审批语义不再等同于“刚生成报告”。
- 论文声明能与 AI 日志做双向一致性检查，无 AI 使用也不会漏声明。
- 内部审计完整性与官方匿名提交各自有清楚边界；比赛提交时只选择明确允许的
  支撑文件。
- 任何审核输入、声明、支撑文件或相应校验器变化后，都必须重新 review、构建
  或批准。
