# Project plans

## v5.1 scope — implemented

- Explicit problem-semantics forks, assumption fingerprints, branch probes,
  nondelegable human decisions and structural sensitivity kept separate from
  parameter sensitivity.
- Structured mathematical modules for symbols, equations, derivations,
  parameters, numerical methods, code mappings and proof obligations.
- Eight ordered v5.1 validation stages integrated directly into G0–G7 rather
  than maintained as a parallel manual lifecycle.
- Fail-closed stage/Gate approvals bound to normalized artifact, schema and
  validator hashes; empty scaffold files do not count as completed audits.
- Dedicated math-scope and full-manuscript strong-claim scans with separate,
  current receipts and evidence provenance.
- Blind-review responses bound to exact packet, run and review identifiers,
  with named-human independence attestation.
- Plan-resolved abstract generation, section-quality/citation/equation
  registers, strict PDF receipts and provenance-bound delivery packaging.
- Canonical JSON/CSV schema routing, named-human identity enforcement and
  timezone-aware review/approval records across scientific and paper controls.

## v4.1 scope — implemented

- Evidence-first manuscript architecture after scientific freeze.
- Bounded section-writing packets and dedicated section writers.
- Deterministic manuscript assembly, claim/evidence trace lint and finalization.
- Independent paper/red-team/compliance audit bound to exact draft and freeze hashes.
- Final manuscript generation with internal trace tags removed.

## v4.0 scope — implemented

- Runtime-neutral scientific core with Codex, Claude Code and Claude Code + DeepSeek adapters.
- One canonical agent-role registry and one canonical Skill tree.
- No fixed Agent count and no majority-vote selection.
- Problem Graph, module-level integration and evidence-first model selection.
- Separate per-provider API budgets and bounded direct-provider calls.
- Faithful and Lite verifier backends remain explicitly distinct.

## Candidate future work

- Strict filesystem allowlists/worktrees for blind explorers across every runtime rather than relying partly on role instructions.
- A native provider-agnostic tool loop for Direct API mode with audited read/write/execute capabilities.
- Optional embedding-based semantic clustering for Idea Cards.
- Solver adapters for OR-Tools, Pyomo, Gurobi, MATLAB and Julia.
- Automated claim extraction from LaTeX with human confirmation.
- Local dashboard for queues, budgets, evidence, disputes and verifier tournaments.
- Evals over past CUMCM problems comparing runtime/provider mixes and orchestration policies.
- A single typed lifecycle-event journal with append-only integrity and stable
  semantic projections for Gate/stage approval evidence.
- Faster incremental test layers that preserve the full release suite while
  shortening local feedback for one changed contract.
